# Task #194 Review benchmark corpus

This directory freezes the first Review Eval corpus for Task #194. It contains
two self-contained Git-bundle fixtures, their immutable identity manifests, the
frozen Task Contract and deterministic identity evidence. The fixture bundle is
the only Subject input to a replay.

## Fixtures

| Fixture | Role | Frozen head |
| --- | --- | --- |
| `task-194:defect-rich-v1` | Historical defect-bearing Subject used to measure known-finding recall | `929ce3dfc71846c4d40a3ce8a05215345be8bc33` |
| `task-194:stable-v1` | Historical repeated-PASS control; not a proof of zero defects | `3b1cbbd6db08ae81506c9b70ebfc7eabd7b8cf70` |

Both fixtures freeze the same Task #194 base, contract, and evidence category.
The Git bundles allow recovery in a fresh independent materialization without
depending on the current branch or current GitHub PR.

## Replay boundary

`lck_core.review_benchmark.ReviewBenchmarkRunner` reuses the immutable
Harness/Subject/Run boundary from `lck_core.review_eval`. A semantic protocol
receives only the current Harness and one read-only historical Subject. The
scorer-only oracle is loaded after the protocol returns and is never copied into
the Subject, environment, import path, or protocol callback.

The initial baseline uses the deterministic Task #194 adapter because this
repository has no model-provider runtime. It follows the production-shaped
`Inspect → Reason → Judge → Report` boundary and records model/config, token
accounting, wall-clock time, findings, verdict, protocol identity, and Harness
SHA. Future provider-backed runs can use the same protocol callback and receipt
schema.

Run receipts are generated by the acceptance test in an operation-owned
temporary directory. They are bounded evidence, not GitHub lifecycle authority.
Raw rollout logs, credentials, and local workflow artifacts stay outside the
repository.
